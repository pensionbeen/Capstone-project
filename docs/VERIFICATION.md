# 검증 근거·완료 판정·진행률

T-008은 사용자가 직접 확인한 결과와 근거를 완료 조건에 연결한다. AI의 응답이나 실행 종료는 기능 완료를 만들지 않는다. 실제 프로젝트는 SQLite에 저장하고 예시 프로젝트는 현재 창에서만 유지한다.

## 사용 방법

1. 기능에 확인 가능한 완료 조건을 적는다. 묶음에는 완료 조건이나 통과 기록을 직접 넣지 않는다.
2. **기능 검증 → 검증 결과 기록**에서 포함된 말단 기능을 선택한다. 직접 확인한 조건을 선택하고 실제 관찰 결과·검증 근거 설명을 입력한다.
3. 모든 조건을 확인해야 **모든 조건 통과**를 저장할 수 있다. 일부 또는 전체가 실패하면 **수정 필요**로 기록한다. 두 결과 모두 관찰 결과와 근거가 필요하다.
4. 기록에서 확인한 조건 목록·조건 버전·날짜와 시각을 확인한다. 조건이 달라진 기록은 **이전 조건의 결과**, 같은 조건의 예전 기록은 **이전 검증 기록**으로 표시한다.

근거는 텍스트 설명이다. 파일 업로드·내용 검사나 AI 문장의 진위 판별을 수행하지 않는다. 사용자가 체크한 조건과 입력한 결과를 수동 확인 기록으로 저장하며, 실제 동작을 독립적으로 보증하지 않는다.

## 완료와 진행률 규칙

- 진행률은 **포함된 말단 기능 중 현재 버전의 최신 유효 통과 수 / 포함된 말단 수**다. 묶음과 제외된 기능은 세지 않는다. 말단이 0개면 **정의 전**이며 100%로 계산하지 않는다.
- 기능 추가·삭제·제외·재포함마다 다시 계산한다. 제외 자체는 조건 변경이 아니므로 기록을 보존하고 **진행률에서 제외**로 표시한다. 같은 조건으로 재포함하면 기존 결과를 다시 사용할 수 있다.
- 제목·설명·완료 조건·관련 경로·선행 관계를 바꾸면 조건 버전을 올리고 이전 근거를 보존한다. 상위 묶음 이동·순서·포함 여부만 바꾸는 경우에는 버전을 올리지 않는다. 선행 기능 삭제로 관계가 바뀐 기능도 재검증한다.
- 같은 버전에서는 시각이 나중인 기록을 적용한다. 배열이나 DB 행 순서에 의존하지 않는다. 정확히 같은 시각에 상충하는 결과가 있으면 **실패를 우선**한다. 새 화면 기록은 저장된 최대 시각보다 최소 1ms 뒤로 만들어 연속 입력·시계 역행에도 순서를 유지한다. 이 경우 표시 시각은 컴퓨터 시각보다 앞설 수 있다.
- 나중 실패는 이전 통과를 완료 집계에서 제외한다. 이후 현재 조건의 새 통과를 기록하면 다시 완료로 계산한다. 이전 기록은 남는다.

## 저장과 실패 처리

화면과 저장소는 공통 입력 규칙을 사용한다. 저장소는 기존 계획과 비교하여 같은 버전의 내용 변경·버전 되돌리기·살아 있는 기능의 기존 검증 수정/삭제를 거부한다. 새 기록은 현재 기능의 버전과 제목을 참조해야 한다. 기능을 삭제하면 해당 기능의 기록도 함께 삭제하는 기존 계약을 유지한다.

저장이 실패하면 기존 데이터와 편집 입력을 유지한다. 저장 성공 응답을 받은 뒤에만 화면의 완료 판정과 진행률을 바꾼다. SQLite 버전은 v3 그대로이며 별도 DB 변환은 없다. 안전 사본을 만든 뒤 과거 백업을 복원하는 경로는 일반 편집과 구분하므로 v1/v2/v3 복원은 계속 지원한다.

공통 계산은 `shared/verification.ts`, 변경 비교는 `shared/feature-plan-transition.ts`, 저장 경계는 `ProjectStore.saveFeaturePlan`에 있다. [저장·복원 안내](PROJECT_STORAGE.md)와 [현재 작업 기록](work-log/2026-10-12.md)을 함께 참고한다.
