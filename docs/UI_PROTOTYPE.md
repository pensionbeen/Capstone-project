# ORBIT UI 프로토타입

**T-011 기능 대화:** 기능·파일 관리와 작업 내용에서 저장한 말단 기능의 Codex 대화를 연다. 선택한 기능과 실제 대화에 연결된 기능·버전·조건·경로를 구분하고, 대시보드에서 현재 실행과 수동 검증 결과를 별도로 표시한다. 화면 이동·중단·새 세션·조건 변경 안내를 제공한다. [사용 방법과 미지원 범위](FEATURE_SESSIONS.md).

**T-008 검증 화면:** 현재 조건의 최신 유효 결과만 완료로 집계하며, 묶음·제외 기능을 분모에서 뺀다. 검증 기록에서 조건 목록·버전·날짜/시각과 과거/제외 여부를 구분한다. AI의 완료 문장만 입력하고 조건을 확인하지 않으면 통과를 기록할 수 없다. [검증·진행률 사용 방법](VERIFICATION.md).

**T-007 기능 편집 (WL-20261011-01):** 기능·묶음 추가/수정/삭제, 선행 관계·관련 경로, 실제 파일 트리, SQLite v3 저장/재시작 복원을 구현했다. 실제 폴더 선택 → ‘이 프로젝트로 시작’ → ‘기능 직접 정리하기’ 또는 ‘저장한 기능 이어서 열기’ → ‘기능·파일 관리’에서 확인한다. [저장 안내](PROJECT_STORAGE.md)·[검토표](reviews/2026-10-11-gemini.md).

기능/묶음은 합쳐서 100개, 파일 트리는 폴더별 200항목·깊이 16까지 표시한다. 프로젝트 안의 2MiB 이하 파일은 고정 메모장으로 열도록 전달한다. 기능 삭제가 소스 파일을 지우지는 않는다. 저장/AI 실행 중 변경을 막는다. 저장 실패 때 편집 입력과 기존 저장 상태를 유지하고, 취소하면 변경을 적용하지 않는다. 알림은 성공 체크·노란 주의 삼각형·오류 표시를 구분한다. 임시 프로젝트 ID를 등록 전에 조회하던 문제도 수정했다.

10-06 전체 Electron UI 32개 통과·실제 계정 2개 skip. 10-11에 지연된 크기 응답 중 연속 변경과 늦은 상태 응답을 별도 확인했다. 아래 날짜별 검사 수는 해당 시점의 결과다.

2026-10-04 · 최신 WL-20261004-05. T-002 화면 흐름에 T-003 실제 Codex 대화를 연결했다. 프로젝트명은 사용자가 지정한 ORBIT이다. 앱 기능 전체의 완료를 뜻하지 않는다. [AI 연결 안내](AI_CONNECTION.md)에 사용 순서·검증 조합·제한을 둔다.

## 화면과 디자인

흰색·연한 회색에 파란색 `#2864ef` 한 가지를 강조색으로 사용한다. 큰 제목, 짧은 안내, 넓은 여백으로 다음 행동을 구분한다. 그림자·그라데이션 없이 기능 목록을 행으로 묶고, 주요 버튼은 화면마다 한 가지 작업에 집중한다. 시스템 한글 글꼴과 직접 작성한 SVG 아이콘을 사용하며 외부 글꼴·이미지를 요청하지 않는다.

| 순서 | 화면 | 사용자가 하는 일 |
|---|---|---|
| 1 | 프로젝트 선택 | 폴더를 선택하거나 ‘예시 열기’로 체험 |
| 2 | AI 연결·보호 설정 | 사용할 AI 복수 선택, 필요하면 보호 설정 펼치기 |
| 3 | 요구분석 | 실제 폴더는 Codex 목표·질문·답변/정정·기능 초안, 예시 프로젝트는 예시 질문 |
| 4 | 기능 확정 | 초안·완료 조건 편집, 포함할 기능 선택 |
| 5 | 작업 대시보드 | 다음 작업·검증 상태 확인, 기능 상세 열기 |

초기 단계는 앞 단계를 마쳐야 이동할 수 있다. 대시보드에서는 기능 검증·보호 정책·파일 전송·실행 이력으로 이동한다. 작은 화면에서는 메뉴를 접고 내용을 세로로 배치한다. 키보드 초점, 본문 바로가기, 입력 이름, 모달 닫기, 동작 축소 설정을 지원한다.

Codex·Gemini를 각각 선택/해제할 수 있다. 최소 한 도구를 선택하면 다음 단계로 진행하며 단계 이동 뒤 선택을 유지한다. 선택 목록은 대시보드·보호 정책·화면 조작 이력에 반영한다. AI별 역할 배정·자동 호출·작업 인계는 아직 구현하지 않았으며 실제 AI 연결 이후 설계·구현할 사항이다.

## 실제 구현과 예시의 경계

- **실제 동작:** Electron 창, 폴더 선택 요청과 경로 검사, 단계 이동, 입력·기능 편집, 검색·필터, 사용자가 직접 남기는 검증 결과와 진행률, 보호 규칙 초안, 파일 이름·크기 미리보기, 실제 화면 조작 이력.
- **실제 AI 대화:** 실제 폴더 선택 후 Codex 대화 열기·설치/로그인 확인·메시지 전송·출력·중단·이어서 보내기. Gemini 선택은 유지되지만 실제 실행은 Codex 한 개다. 대화 화면 이동 시 실행이 유지되며 앱 종료 시 정리를 확인한다.
- **요구분석·생성:** 실제 폴더에서는 Codex와 목표·질문·답변/정정을 나누고 검사된 기능 초안을 편집 후 기존 목록에 추가한다. 적용 전에는 저장하지 않는다. 예시 프로젝트만 고정된 예시 질문·생성 규칙을 유지한다. [사용 안내](REQUIREMENTS.md).
- **미구현:** 기능별 AI 실행·역할 배정·다중 AI 실행, OS 파일 보호 적용, 두 기기 연결·파일 전송, 요구분석·대화/활동 이력의 영구 저장. 파일 전송 화면은 파일 내용을 읽거나 업로드하지 않는다. 활동 이력은 AI의 파일 접근 감사 기록이 아니다.
- **저장 범위:** 프로젝트·기능·관계·경로·검증 기록은 SQLite에 저장한다. 요구분석 입력·보호 초안·대화/활동 이력은 현재 실행의 메모리에만 있다. 대화 출력은 주 프로세스가 제한된 크기로 보관하므로 대화 화면을 닫아도 유지된다. Codex 자체 대화 기록은 사용자 환경에 남을 수 있다. 폴더 선택 자체는 프로젝트 파일을 읽거나 수정하지 않는다.

진행률은 포함된 기능 중 현재 완료 조건 버전에 유효한 통과 기록의 비율이다. 통과를 기록하려면 완료 조건 확인·관찰 결과·근거를 입력해야 한다. 내용이나 조건을 바꾸면 재검증이 필요하다. 새 초안은 새 기능 ID를 사용하며 이전 검증을 물려받지 않는다. 자동 검사나 AI가 검증한 결과로 표현하지 않는다.

## 실행

검증 환경은 Windows x64, Node.js **24.15.0**, npm **11.12.1**, Electron **44.5.1**이다. 저장소 루트의 PowerShell에서 실행한다.

```powershell
npm.cmd ci
npm.cmd run setup:electron
npm.cmd run dev
```

Electron 실행 파일이 아직 없으면 `setup:electron`이 내려받는다. 이 환경에서는 일반 의존성 설치 뒤 별도로 실행했다. 인터넷 접근이 필요하다. 잠금 파일 기준의 깨끗한 `npm ci` 재설치는 이번에 다시 수행하지 않았으며 실제 설치는 `npm install`로 확인했다.

빌드한 화면을 열려면 다음을 실행한다.

```powershell
npm.cmd run build
npm.cmd start
```

브라우저 전용 확인은 `npm.cmd run dev:web` → `http://127.0.0.1:5173`이다. 브라우저에는 데스크톱 폴더 선택 기능이 없으므로 ‘예시 열기’를 사용한다. 설치 프로그램 생성·코드 서명·배포는 후속 T-020/T-101 범위다.

## 구조와 검사

- `src/`: React 화면과 현재 실행의 상태. `src/model.ts`: 화면 모델·초안 규칙. `shared/verification.ts`: 화면과 저장소가 공유하는 검증·진행률 규칙.
- `electron/`: 창, 정적 자원 제공, 폴더 선택·기능 저장·파일 목록/열기·AI 대화의 고정 접점만 노출하는 제한 통신. `electron/ai/`: Codex 확인·PTY 호스트·출력/수명/프로세스 관측. `shared/`: 통신 타입.
- `scripts/dev.mjs`: 개발 서버와 Electron 실행·종료 관리.
- `tests/`: 계산·경로·권한 경계 및 실제 Electron 화면 자동 검사.

```powershell
npm.cmd run lint
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run test:ui
```

최신 WL-20261004-05 결과: 형식·타입·빌드 통과, 로직/경계 **19개**, PTY 합성 **2개**, Electron 화면 **11개** 통과. 실제 계정 검사 **2개**는 별도 실행해 통과했다. 이전 UI 묶음의 로직 12개·화면 9개, 도구 작업 프로세스 종료 코드 `3221226505`와 재실행 이력은 WL-03/04에 보존한다. 이번 전체 UI 실행에서는 재발하지 않았으며 과거 원인은 미확정이다.

폴더 자동 검사는 **OS 대화창의 반환값만 대체**하고 실제 파일 시스템과 앱 처리 흐름을 검사했다. 이후 사용자가 실제 Windows 폴더 선택·변경 취소 후 기존 선택 유지를 직접 확인해 **T-002를 완료**했다. 이 검사로 OS 보호를 입증하지 않는다.

후속 복수 선택 수정(WL-20261004-04): 형식·타입·빌드 통과. 기존 화면 검사에 두 도구 선택·개별 해제·0개 차단·키보드 선택·이동 후 유지·보호/이력 반영을 추가했다. 전체 실행은 8개 통과·작은 화면 검사 시작 전 작업 프로세스 종료였고, 작은 화면 검사만 재실행해 통과했다. 이 결과를 한 번의 9개 전체 통과로 표현하지 않는다. 기존 로직 12개 결과는 이전 UI 구현의 검사다.

화면 캡처는 `.runtime/screens/`에 생성되며 Git에서 제외한다. 수정 뒤 `npm.cmd run build` 후 화면 검사를 실행해야 최신 빌드가 검사된다.

보안 구조 참고: [Electron 공식 보안 안내](https://www.electronjs.org/docs/latest/tutorial/security), 개발 도구 참고: [Vite 공식 안내](https://vite.dev/guide/). 실제 구현은 renderer의 Node 접근 차단·격리·샌드박스, 요청 창·프레임·출처 검사, 창 열기·권한 요청 차단을 포함한다. 이는 별도 AI 프로세스의 OS 파일 접근 보호와 다른 경계다.
