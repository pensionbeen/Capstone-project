# 프로젝트 목표·요구사항·근거

작성 기준: 2026-10-03, Asia/Seoul(한국시간). 이 문서는 개발계획이다. 기능 구현·실행 검증 보고서가 아니다.

## A. 최종 프로젝트가 해결할 문제

터미널 AI를 사용하는 1인 개발자가 여러 창을 반복해서 확인하고, AI 작업과 기능·파일·완료 근거를 연결하기 어려운 문제를 해결한다. Windows 데스크톱 앱에서 프로젝트 목표를 대화로 정리하고 작은 기능으로 나누어 실행·검증·기록한다. AI가 접근해서는 안 되는 파일은 OS가 접근 전에 거부하고, 같은 네트워크의 다른 기기로 사용자가 선택한 파일을 보낸다.

핵심 흐름은 **프로젝트와 폴더 선택 → AI 연결·보호 정책 확인 → 목표 입력·추가 질문 → 기능 생성·사용자 편집·적용 → 기능에 AI 세션 연결 → 상태·기록 관찰·필요시 중단 → 완료 조건 검증 → 진행률 반영 → 선택적 파일 전송**이다.

대상 사용자는 우선 Windows에서 터미널 AI를 사용하는 단일 사용자다. 조직 권한·다중 사용자 서버·중앙 클라우드 저장소를 추가하지 않는다. 개발 인원은 1명이다.

## B. 프로토타입과 최종 결과의 차이

- 프로토타입 내부 마감: **2026-10-19 23:59 KST**. 학교 최종 제출일이 아니다.
- 실제 동작 목표: R-01~R-08의 한 흐름, R-09~R-10의 지정 경로 OS 거부, R-11~R-12의 두 기기 단일 파일 전송. 화면 이동·재시작·주요 실패도 시험한다.
- 화면 시연: 전체 화면 흐름·미지원 상태 안내를 먼저 볼 수 있으나, 가짜 데이터·모의 결과는 명시한다. 보호 활성·전송 성공을 가짜로 표시하지 않는다.
- 기술 실험: X-001 AI, X-002 OS 보호, X-003 두 기기 전송은 호환성·채택 판단용이다. 성공 실험이 앱 통합 완료를 대신하지 않는다.
- 최종 단계: 프로토타입에서 남은 핵심 결함 해결, 설치·업데이트·복구·성능·보안 반복검증, 학교 시연·보고서·발표·최종 확인.
- 후속 확장 제안: 다중 AI 동시 실행, 기존 외부 터미널 사후 연결, 자동 탐색·폴더 전송·이어받기, 복잡한 마인드맵·단독 AI 화면. 이번 확정 범위에 자동 포함하지 않는다.
- 프로토타입 필수에서 제외하는 기존 제안: 커널 드라이버 직접 개발, 전체 파일 I/O 가로채기, 가상 파일 시스템, 원문 마스킹, 패킷 차단. 접근 거부 목표를 약화하는 허가는 아니다.
