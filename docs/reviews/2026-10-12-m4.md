## 의견별 타당성 대조

| 의견 | 실제 원문·재현 결과 | 판단·처리 |
|---|---|---|
| 생성 응답의 CRLF 문자열·대문자 JSON fence 허용 제안 | 계약은 엄격한 순수 JSON이며 필드·개행·경로 제한을 검사한다. 실제 Codex 응답은 현재 계약으로 기능2개를 생성했다 | 비필수 호환 제안으로 미반영. 허용 형식을 이유 없이 넓히지 않음 |
| 정상 종료 후 host.pid가 남아 cleanup이 영구 false | pid 없음은 spawn 실패 분기다. 정상 pid이면 즉시 ProcessAudit를 만들고 관측한 후손의 소멸로 정리를 판정한다. 실행 파일 부재 검사도 cleanup=true로 통과 | 발췌에서 빠진 시작 코드를 대조해 미채택. Gemini도 추가 원문 뒤 철회 |
| ownerKey 관측 전 PTY가 실행/종료될 수 있음 | 주 루프는 audit.observe 성공 뒤 start IPC를 보내고 호스트는 그 메시지를 받은 뒤 pty.spawn한다. 최초 관측 실패는 실행 전 차단한다 | 미채택, 추가 원문 검토도 반례 없음. 실제 PTY 검사2개 통과 |
| 부모가 종료된 미관측 자식을 uncertain으로 두는 오류 | PID만으로 소유자를 추측하지 않는 기존 계약이다. 이미 관측한 자식은 부모 종료·외부 부모로 이동한 뒤에도 owned에 남는다. 계보 누락·시간 역전·순환은 차단 검사 통과 | 미채택, Gemini도 의도된 경계로 재평가. 실제 PID 재사용 오탐은 별도 근거로 수정함 |
| 같은 대화에서 초안 취소 후 재생성 시 id가 같아 표시 안 됨(P1) | [SessionManager](../../electron/ai/session-manager.ts)의 startTurn은 매 실행 randomUUID로 id를 새로 만들며 conversation/outputId와 다르다. 실제 Electron 검사에서 취소→재생성→미리보기 표시, 같은 conversation/outputId·다른 runId를 확인했다 | 지적의 전제가 달라 미반영. 이 의견 뒤 제품 코드 변경 없음 |
| 생성 중 generationState 확인이 없어 버튼이 활성화됨(P2) | [생성 패널](../../src/components/FeatureGenerationPanel.tsx)은 snapshot.state의 starting/running/stopping을 차단하고 cleanupConfirmed·pending도 검사한다. 실제 ‘기능 초안 만드는 중’ 버튼 비활성 확인. 서버는 실행 중/오래된 ID/중복 요청을 거부한다 | 중복 생성 결함 미재현으로 미반영. IPC 접수와 다음 상태 조회 사이의 표시 지연까지 없다고 주장하지 않음 |
| 저장 실패 메시지가 초안 때문에 숨겨짐(P2) | error prop은 [미리보기](../../src/components/FeatureDraftPreview.tsx)의 role=alert로 표시한다. 해당 렌더링은 전달문 발췌에서 빠졌다. 실제 저장 실패 메시지 표시·편집 내용/DB 보존·재시도 성공·앱 재시작을 확인했다 | 전체 원문과 화면 검사로 미채택. 중복 오류 배너를 추가하지 않음 |

UI 지적 대조를 위해 제품 코드 수정 없이 기존 통합 검사2개를 확장했다. **17:06 KST 확인: 2개 모두 통과(48.0초·35.5초)**. 별도 Edge 응답/통신42회 오류0이었다. AI 의견을 부정한다는 선언 대신 재현 동작을 근거로 판단했다.

## 실제 원인을 확인하고 수정한 프로세스 문제

최초 실행 검토에서 종료한 agy.exe의 PID13940(생성07:03:00.557Z)을 외부 git.exe(07:06:48.887Z)가 재사용했고 자식 git.exe가07:06:48.907Z에 생성됐다. 기존 판정은 부모 PID 숫자만 대조해 불확실로 남겼다. 개발 보조와 앱의 감시 구현 모두 새 부모의 생성 시각·현재 신원·완전한 외부 계보를 확인할 때만 이 경우를 제외하도록 Codex가 수정했다. 새 검사12개 중 수정 전2개 실패를 확인하고 수정 후12개 통과, 기존 검사5개도 통과했다.

알 수 없는 프로세스를 강제로 종료하거나 실패 시 자동으로 보호를 풀지 않는다. 이 수정은 관측 증거가 있는 PID 재사용을 구분할 뿐 미관측 고아·같은 감독자 아래의 새 콘솔·불완전한 계보까지 안전하다고 취급하지 않는다. 세부 분담은 [병렬 개발 기록](../PARALLEL_DEVELOPMENT.md), 앱/다른 앱 검증과 남은 범위는 [작업 기록](../work-log/2026-10-12.md)을 따른다.
