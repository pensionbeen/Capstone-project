## 기본 의견의 근거

- **review-boundary-1:** 실제 전용 프로젝트 정책은 file://C: 주소와 소문자 UUID를 저장하고 현재 verifier가 통과한다. 1.2.17 실제 canary는 도구별 ACTIVE→ERROR 총 8사건이며 네 명시적 deny가 확인됐다. 지원하지 않는 주소/ID/이벤트는 오류 보고로 차단하는 동작이며 즉시 크래시가 아니다. 읽기 전용 Astra 요청 보조도 정책 해시와 증거를 직접 대조했다.

- **codex-pty-1:** Codex 실험의 Sol/High, interrupt 종료1, PTY 통합 스트림과 별도 호스트 stderr는 각각 확인한 실제 계약이다. 이번 Gemini 검토환경의 Pro/High·canary close0를 대입한 지적이라 코드수정하지 않고 설명을 보강해 재검토한다.
- **managed-supervision-1:** 모든 실제 호출자는 단일/순차다. runManagedPlan 13회 동시활성 최대1, 첫 정리실패 후 나머지12회 미실행을 보조가 재현했다. 같은 supervisor에서 미등록 동시query/형제콘솔 생성 시 불확실 판정은 의도된 제한이다. 마지막 조회 이후 PID가 재사용될 수 있어 alive 숫자PID 일괄kill 제안은 소유객체만 종료하는 계약을 깨므로 채택하지 않았다. 알려진 외부 조상 콘솔은 정상 제외된다.

## 이번 실제 확인

- 개발용 Electron 버전 조회: 종료 거부·close 없음·약400KiB 연속 출력에서 보관 상한 검사가 수정 전 실패, 수정 후 통과. X-001 로컬 전체 77개 통과.
- 창 크기 변경: 응답 하나를 붙잡고 화면을 두 번 더 변경한 뒤 응답을 풀어 최종 화면 열 수와 SessionManager 열 수 일치를 확인했다. 정상 poll의 재전달을 검증했으며 앱 코드는 바꾸지 않았다. 조회 자체가 영구 중단된 상황이나 새 실제 AI 계정 검사로 확대하지 않는다.
- 기존 전송 상태 회귀 검사 재통과. 빌드/타입 검사 및 lint 55개 통과. 10-06의 전체 앱 검사 수와 이번 개별 실행 수를 합쳐 새 전체 통과 수로 표시하지 않는다.
- 공식 안내는 보존된 21개 문구 보완과 추가 3개 실패/재개 경계를 실제 구현에 맞춰 반영했다. 복원 실패 시 안전 사본 자동 덮어쓰기나 OS 권한 완화를 추가하지 않았다.
