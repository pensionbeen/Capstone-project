## 사용하는 순서

1. `npm.cmd run build` 후 `npm.cmd start`로 ORBIT을 연다.
2. 실제 프로젝트 폴더를 선택하고 ‘이 프로젝트로 시작’을 누른다. 예시 프로젝트에서는 실제 실행을 하지 않는다.
3. Codex를 선택하고 ‘Codex 대화 열기’ → ‘연결 준비 확인’을 누른다. 검증 대상은 Windows x64·npm 사용자 설치의 Codex 0.160.0·기존 ChatGPT 로그인이다. 다른 버전·API 인증 우회 설정은 실행하지 않고 안내한다.
4. 메시지를 보내면 실행 출력을 받는다. 다음 메시지는 앱이 보관한 정확한 대화 ID로 이어 보낸다. ‘실행 중단’은 요청 뒤 로컬 정리 여부까지 표시한다.
5. 대화 창을 닫거나 다른 화면으로 이동해도 실행은 유지된다. 위쪽 ‘AI 대화’로 다시 연다. 실행 중 프로젝트 변경은 차단한다. 앱 전체 종료는 실행 정리를 기다린다.

대화 입력은 8,000자, 최근 출력 보관은 512 KiB, 조회 한 번은 64 KiB, 실행별 출력은 8 MiB, 실행 시간은 10분으로 제한했다. 보관 한도로 생략한 출력은 표시한다. 정리 미확인 시 다음 실행을 막으며 앱 종료 시 안내한다.

## 구현·실측 결과

`src/components/AIConsole.tsx`의 xterm과 제한 preload 통신을 주 프로세스의 `SessionManager`에 연결했다. 네이티브 폴더 선택으로 등록된 ID만 받으며 실행 파일·인자·환경·대화 ID는 화면에서 지정할 수 없다. 사용자 입력은 고정 접두어·옵션 종료자 뒤의 단일 인자로 전달한다. 별도 Electron Node 호스트가 PTY를 소유하고, 주 프로세스는 PID·생성 시각·부모 관계로 관측한 프로세스를 대조한다.

- 형식·타입·빌드 통과, 로직·경계 **19개**, 실제 Electron Node PTY 합성 검사 **2개**, 전체 Electron 화면 **11개 통과**. 일반 화면 명령의 실제 계정 검사 2개는 의도적으로 건너뛰고 별도 실행했다.
- 실제 계정 검사 **2개 각각 통과**: 한국어 계산 응답과 이전 질문을 기억하는 정확한 대화 재개, 실행 중단 및 실행 중 앱 종료. 중단 출력의 `turn interrupted`도 관측했다. 앱 종료 후 관측한 7개 PID의 프로세스·TCP 연결은 0개였다. 유한한 관측이며 OS 격리나 원격 연산 종료 증명이 아니다.
- 합성 검사에서 한글·옵션처럼 시작하는 입력·실제 크기 변경 표시·같은 ID 재개·중복 시작/프로젝트 변경 차단·중단·512 KiB 초과 출력 보관·앱 종료를 확인했다. 존재하지 않는 호스트와 로그인 조회 close 미도착도 검사했다.
- xterm 동적 스타일에 필요한 `style-src-elem`만 inline을 허용했다. `script-src 'self'`, `style-src-attr 'none'`, 화면 Node 접근 차단·격리·출처 검사는 유지한다. Codex `--color never` 경로와 개발/빌드 화면을 확인했으며 임의 RGB 터미널 색 지원은 보장하지 않는다.
- Astra/Max 요청 읽기 전용 검토의 종료·크기 변경·출력 세대·CSP 문제를 수정했다. 실제 내장 모델 메타데이터는 미확인이다. Gemini Pro/High 독립 검토는 `OWNERSHIP_UNCONFIRMED`로 **코드 전송 전 차단**되어 의견을 받지 못했다. 보호 정책·설정·합성 파일 불변, 관측 후손 0, 잠금 보존을 기록했다.

```powershell
npm.cmd test
npm.cmd run test:ai-runtime
npm.cmd run build
npm.cmd run test:ui
# 기존 Codex 계정으로 실제 네트워크 호출을 수행하는 별도 검사
npm.cmd run test:ai-live
```

실제 계정 검사는 합성 질문과 시험 폴더를 사용한다. 전체 출력·런타임 증거·화면 캡처는 `.runtime/`에 두고 Git에서 제외한다. Gemini 개발 보조의 보존된 잠금은 소유 불확실 사유 확인 전 자동 해제하지 않는다.

## 구현·검증 단위

기존 예상 6~10h를 유지하며 아래 세 단위로 진행한다. 완료 결과는 기능 마무리에 한 번 기록한다.

1. 실행 경계·호스트(2~3h): 주 프로세스가 선택한 프로젝트와 실행 파일·인자·대화 ID를 소유한다. 별도 Electron Node 호스트에 PTY를 둔다. 임의 경로·인자, 중복 실행, 출력 상한, 호스트 종료를 합성 프로그램으로 검사한다.
2. 화면 연결(2~3h): 설치·로그인 확인, 한국어 입력, xterm 출력·크기 변경·중단, 화면 왕복을 연결한다. 실제 계정 연결과 도구 선택을 구분하며 Gemini 복수 선택을 보존한다.
3. 실제 연결·실패 검증(2~4h): Codex 응답·정확한 대화 재개·중단·앱 종료·관측 후손/소켓 정리, 출력 부하와 회귀 검사를 수행하고 기록·검토·작업 브랜치 push를 마친다.

## 이번 연결의 경계

- X-001에서 확인한 native Codex 0.160.0 `exec` 경로를 사용한다. 대화형 TUI의 개인 설정 격리는 미확인이므로 해제하지 않는다.
- Codex 읽기 전용 설정과 ORBIT 보호 경로의 OS 읽기 차단은 다르다. 보호 초안은 적용하지 않으며 보호 적용 실행을 허용하지 않는다.
- 첫 연결은 Codex 단일 실행이다. Gemini 실제 앱 연결, 여러 AI 동시 실행·역할 배정, 기능 완료 판정, 저장은 후속 작업이다. Fastify 로컬 서비스는 후속 T-004에서 연결했다.
- 프로세스 종료는 기능 완료의 근거가 아니다. 중단 후 로컬 프로세스 정리를 확인해도 원격 연산 중단까지 증명하지 않는다.
- 앱 대화는 메모리에 보관한다. Codex 자체 대화 기록은 로그인한 사용자 환경에 남을 수 있다. 자격 증명은 복사하거나 앱 화면에 노출하지 않는다.
- node-pty의 자연 종료 문제 때문에 전용 호스트를 소유자가 종료한다. 번들 ConPTY DLL은 이 프로토타입에서 검증할 후보이며 모든 PC·패키징·OS 격리의 검증을 의미하지 않는다.
